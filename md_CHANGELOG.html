Changelog

All notable changes to libmizu are documented here. The format follows Keep a Changelog. Versions carry an ABI contract: any wire-format change bumps MIZU_ABI_VERSION in include/mizu.h, and the soname tracks MIZU_VERSION_MAJOR.

Added

  • mizu_channel_abandon / mizu_pool_abandon: the forked-child teardown for an inherited handle. Each releases only the process-local half — the child's copies of the mapping and fds plus its heap — and writes no cross-process word (no close signal or shutdown broadcast, no unlink, no slot release, no parker or refcount change), so the creating process's handle and the wire state are untouched. A binding finalizer can now release an inherited handle instead of leaking it (valgrind's default definite,possible leak kinds count such leaks as errors). Calling abandon in the owning process remains a contract violation, as destroy on an inherited handle was and remains.
  • The Arrow frame writer's inline small-table form: mizu_arrow_write_ix (one complete ‘'I’‘ stream of the whole frame — header, attr mark, the list of the columns’ value forms, then the root dict {names, class = "data.frame", row.names = c(NA, -n)}) and mizu_arrow_write_ix_col (one column's value form), both dst-NULL-sizing and built on the per-column writers and mizu_arrow_str_at, the string walk's malformed record put as NA like a null. A below-gate frame now crosses with one C write straight off the Arrow buffers where it previously converted back to a language value first; the stream is byte-identical to the bindings' historical inline emitters (the root dict is always the automatic form — the root-blob override is the region writer's — and the MIZL-only leaves never appear). No ABI bump: a same-language reader already accepts an ‘'I’` stream on the value tiers (the first-byte dispatch precedes the private codecs).
  • The Arrow frame writer's per-column ext writers mizu_arrow_col_body (a column's by-value body bytes over every batch — the same loops the MIZL leaves use) and mizu_arrow_col_blob (its attribute dict as a bare 0x0d dict value, the §3.5 blob without its stream header), both dst-NULL-sizing, so a binding's own ‘'I’emitters share the core's byte-level code instead of copying it. The validity and per-element string accessors move tomizu_ext.has the dual-form mizu_arrow_valid/mizu_arrow_str_at.mizu_arrow_colshrinks to the particulars the emitters still key on (kind,row,str_form, u64_verbatim); the dictionary levels are no longer copied out at open (validation walks batch 0's borrowed dictionary, which the level match and the factor blob now read directly). The frame-size memo re-runs after any override (mizu_arrow_remote/_root_blob/ _tz`), so overrides no longer need to precede the first size call.
  • The Arrow frame writer's verbatim uint64 form: a ‘'L’(uint64) column for a peer advertising the newMIZU_CAP_MIZL_U64Vcapability bit (bit 6) stages as an INT64 leaf — the identity lanes, the validity machinery unchanged — whose attrs blob is{u64 = TRUE}(new vocabulary macroMIZU_IX_ATTR_U64); a peer short of the bit gets the REAL conversion as before.mizu_arrow_warngainsn_int64(a genuineINT64_MINon a masked int64 identity column — reads as NA in R), counted besiden_intminon the masked walk only with the verbatim rows excluded (a twinCVT_ROW_I64_Vkeyed out by pointer compare);mizu_arrow_stagezeroes the struct, so existing initializers are unaffected.mizu_arrow_colgains the u64_verbatimout-field for a binding's own emitters. No ABI bump (capability bits are append-only); the fuzzers need no rows (fuzz_arrowopens caps-less, so its'L'rows stay on the conversion path, as its TSN rows do).
  • The validity section's semantics are normative in DESIGN.md ("validity as data"): when a MIZH/MIZL header's validity pair is not{0, 0}the section is the authoritative null record and the in-band sentinels are the null-slot fill, with the fill invariant (a writer emitting a section writes the wire type's sentinel at every clear bit), the reader rules (a carried bitmap applies verbatim at null-concept boundaries; an absent section derives lazily from the sentinels — one rule for every atomic wire type, REAL's test the payload notisnan) and the writer rules (emit when the source carries a null record;{0, -1}only on data known null-free). The uint64 verbatim form is specified beside it: a 'L'frame column stages as an INT64 leaf with a u64 marker attr for a peer advertisingMIZU_CAP_MIZL_U64V<tt>(bit 6), both bindings advertise, and the degradation for pre-cap readers is channel-scoped. No byte change from the validity declaration: the section needs no capability bit andMIZU_ABI_VERSION` is untouched.
  • The Arrow frame writer (src/arrow.c): an Arrow C Data Interface → MIZL writer in the core, promoted from pymizu's shmframe.c so both bindings stage frames through one implementation. The Arrow structs are defined in mizu_ext.h under the spec's two include guards (ARROW_C_DATA_INTERFACE, ARROW_C_STREAM_INTERFACE). The interface: mizu_arrow_open (classify + batch vetting + dictionary validation, the decline in the thread-local slot naming the column, its format and the remedy), the mizu_arrow_remote / mizu_arrow_root_blob / mizu_arrow_tz overrides, mizu_arrow_size, mizu_arrow_stage (the one-call stage over the handle seam — the capability conjunction and the churn check now have one home), mizu_arrow_col_info (the per-column plans for a binding's own emitters) and mizu_arrow_close, with the mizu_arrow_warn conversion counts out-param. The fixed-width conversion kernels export as mizu_cvt_for_arrow / mizu_cvt_convert over the mizu_cvt_row table (MIZU_CVT_*). The type map: bool → LGL, int8/int16/uint16 → INT, uint8 → RAW (nulls decline), int32 → INT, uint32 → REAL, int64 → INT64, uint64 → REAL (past 2^53 → NA, counted), float16/32/64 → REAL, utf8/large_utf8/string_view → MIZS, dictionary<strings> → factor (ordered declines), date32 / timestamp / duration → REAL + the Date / POSIXct / difftime blobs. The producer's validity bitmap is authoritative (copied verbatim for a single offset-0 batch, rebuilt honouring batch->offset otherwise) and the data carries the R sentinels at null slots — the write is always the foreign form (bulk CE_UTF8 marks + the validity tail), so the bytes are peer-agnostic. No wire change: MIZU_ABI_VERSION is untouched.
  • The Arrow frame writer's nanosecond temporal form: a timestamp[ns] / duration[ns] column stages as a verbatim INT64 leaf (the counts unrescaled, NaT the INT64 sentinel) whose attrs blob adds tscale = "ns" beside the POSIXct/tzone or difftime/units pairs, gated per column on the new MIZU_CAP_MIZL_TSN capability bit (bit 5) — a peer short of the bit gets today's REAL-seconds write with the 1e-9 rescale, and a reader short of it fails informatively on the form, never a silent mis-read. New attr vocabulary macro MIZU_IX_ATTR_TSCALE. The verdict resolves once at classify (peer_caps is already in hand), so the size and write passes cannot diverge. No ABI bump: capability bits are append-only and absent means unsupported.
  • The byte-shape helper registry (DESIGN.md's Interchange codec section): the 'I' machinery that operates purely on byte spans and cursor items moves into the core so no byte-level rule keeps a second implementation free to drift across bindings. New dual-form helpers mizu_ix_utf8_valid (strict RFC 3629 validation — the cursor's own string checks now single-source through it), mizu_ix_tag_of (the wire-type → vector-tag table; mizu_ix_put_vec's internal switch single-sources through it), and mizu_ix_write_err (the bounded err framer — type capped at its 128-byte share, message at half the inline budget, detail at the remainder, each cut at a UTF-8 boundary, so the stream fits the slot by construction and cannot fail), with the budget constants MIZU_IX_ERR_OVERHEAD / MIZU_IX_ERR_TYPE_SHARE in the header as the wire authority. New exported-only task-stream decode shim mizu_ixt_open / mizu_ixt_want_code / mizu_ixt_want_list / mizu_ixt_want_dict — the per-field shape checks every task decode shares, recording the normative texts in the thread-local slot so they are byte-identical across bindings by construction. New attr vocabulary macros MIZU_IX_ATTR_* / MIZU_IX_CLASS_* / MIZU_IX_UNIT_* (the shape whitelist's 7 keys, 6 class strings and 5 difftime units; append-only). No wire change: the golden corpus passes unmodified and MIZU_ABI_VERSION is untouched.
  • The MIZL remote leaf (directory tag 33) is normative in DESIGN.md (the follow-ups plan's F2 — a per-column REF): the entry's data_offset / data_size hold the view layer's identifier span (the 0x13 ref leaf's byte form, 1–255 bytes), length and attrs_size describe the referenced column as resolved, the S4 bit rejects, and the validity pair is a {0,0} / {0,-1} claim alone — a remote column contributes no bitmap and no count to the header validity (the vcount bound over local atomic leaf lengths forces the exclusion), and a {0,-1} claim is validatable only against a referenced form that records known-NA- free itself. Resolve-time validation compares the claims against the resolved leaf; a dangling identifier, a parse failure or any mismatch declines as a corrupt region. Emission gates on the new MIZU_CAP_MIZL_REF capability bit (bit 4), per frame. The layout checks admit the tag: mizu_ext_mizl_tag_ok lists it, mizu_ext_mizl_ent exempts it from the attrs-tail and body checks and bounds the span, and mizu_ext_mizl_elem rejects a nonzero validity offset on it. New fuzz_mizl harness over the directory parser. No ABI bump.
  • The ref leaf (‘'I’tag 0x13) is normative in DESIGN.md (the follow-ups plan's F1 — task arguments by reference): u8 length (1–255) plus the view layer's identifier bytes, an ordinary value in the cursor's grammar (the cursor checks the length and bounds only), taken by the task-stream exec decode, the map descriptor reader and the collect-side result reader, and declined informatively everywhere else. The task prose gains the retain protocol: the submit-side pin to the worker's counted-add handoff (no keeperless claim on a ref-carrying frame), the worker's emitted-set release discipline after the outcome write, the consumer-death rule for a kill mid-task, and the single-checkout SHM_VEC constraint with its size-pass-first resolution. Emission gates on the newMIZU_CAP_TASKREFcapability bit (bit 3). New dual-form emit helpermizu_ix_put_ref`; the cursor gains the 0x13 case; the corpus pins task rows with ref arguments, the builder decline at a channel value site, and the empty / truncated cursor rows.
  • The task kind registry's kind 2 (runner) row and the cross-language map's wire forms are normative in DESIGN.md (Phase 5): the runner's fields — region name, the ordinal and morsel generation packed in one i64 (ordinal the high 32 bits), the seed as nil or the (seed, offset) i64 pair — the ‘'I’map descriptor (list[task, x | nil], the f spec nested as a kind 0/1 task tag), the oneMIZU_MORSEL_MAGIC‘ with the descriptor's codec identity riding its own first byte, the per-binding runner result shapes with the foreign-collect normalization rule, and the per-element map error's index on the err tag. No code change (the cursor has parsed kind 2 since Phase 0); the implementing phases are the bindings’.
  • The task tag (0x12) format is normative in DESIGN.md (Phase 4): the fixed-offset header (target, kind, reserved-zero flags, submitter identity) with the SHM_RAW resolution rule, the misroute guard ("task language mismatch"), the submitter identity as the ERR-format and result-policy key with the foreign writer policy for results, the no-keeperless rule for task streams, the source-kind trailing-expression convention, and the neutral error stream for a foreign private frame at a worker. Changed

  • Wire format (pool): the injection/deque entry header carries the result slot's incarnation sequence (rs_seq) — mizu_entry_hdr grows to 40 bytes with the payload at offset 40 — and the result states gain MIZU_RS_LOST (mizu_pool_status.tasks_by_state grows to 7 entries). Pre-release: MIZU_ABI_VERSION stays 1 (peers are same-build; an old reader fails safe) — the standing exception to the bump-on-any-wire-change rule; both bindings re-vendor.
  • Ext tier: mizu_result_publish_died is renamed mizu_result_publish_lost and publishes MIZU_RS_LOST — the payload-vanished terminal no longer carries a worker-death verdict (the claimant is alive; it is publishing), so the collect claim performs no force-reclaim of the claimant's lent regions and builds no claimant record (died_slot -1, died_pid 0). MIZU_RS_DIED is once more the lock-verified reaper's terminal alone.
  • Version macros 0.1.0 (the ext tier's pin for the rename).
  • mizu_arrow_open's duplicate-name check is O(ncols) — an open-addressed table over the name hashes, strcmp on a hash hit only — replacing the quadratic pair scan a wide frame paid per send.
  • mizu_morsel_layout / mizu_morsel_hdr_check lose the magic parameter: the morsel module stamps and checks the one core-owned MIZU_MORSEL_MAGIC (0x4D495A4D — mizu's value, so only pymizu's map regions change magic; the descriptor's codec identity rides the descriptor stream's own first byte). Ext-tier signature change.
  • mizu_mizh_check gains the valid out-param (the MIZH validity section, bounds-checked and handed back). Ext-tier signature change.
  • mizu_channel_recv_batch_fn returns every message it consumed: a read failure after the first message now ends the batch early with MIZU_OK and the prefix instead of MIZU_ERR dropping it, and the failing slot stays at the head so the next receive reproduces the failure (and makes the consume decision — MIZU_READ_CONSUME is honoured on a single receive and a batch's first message only). No wire-format change.
  • mizu_pool_collect_all_fn on a first non-OK outcome now claims the reported handle alone: the OK results ahead of it are no longer consumed and dropped — every other handle stays collectible, symmetric with the timeout case. No wire-format change.
  • mizu_pool_leave now fails the worker's announced in-flight claim as DIED: an orderly leave after an exec_fn infrastructure failure no longer strands the claimed task PENDING — the collector gets the worker-death verdict without waiting on a reaper. No wire-format change.
  • mizu_stage_fn gains the binding ctx; mizu_exec_fn receives a read ctx in place of the bare binding ctx.
  • mizu_pool_collect_all / mizu_pool_collect_all_fn gain a consumed_out param: a read failure after an all-OK wait returns MIZU_ERR with the failing slot's index in err_index_out (unconsumed when retryable) and the number of leading results already handed to the sink / written to values_out in consumed_out — the consumed prefix the bindings previously discarded (R-12 / P-04 adopt it). n on a fully collected run, 0 when the run reports a non-OK outcome or times out. Ext-tier signature change; no wire-format change.

Fixed

  • A worker dying between its claim announce and the claim CAS no longer lets the still-queued entry execute against the slot's next incarnation: the announce (and the sink) now carry the entry's own incarnation stamp, and pool_execute drops a claimed entry whose stamp no longer matches the slot (or whose status is already terminal) without executing, consuming, or stamping worker_slot. Previously the reaper failed the announced slot DIED, the submitter recommitted it, and the zombie's publish won the new incarnation's slot — the collector read the dead task's value for the new task.
  • The lent-region ledger keys a worker handle's two consumer namespaces in one tagged space (MIZU_LED_SUB / MIZU_LED_WK in the key's high half): a worker-death force-reclaim of slot k no longer reclaims result regions lent to submitter k (still held by live views), which the next spill stage would have overwritten.
  • mizu_result_publish_lost (née _died): a transient/torn payload open on a live thief no longer produces a DIED claim whose force-reclaim treated the live claimant's lent regions as leaked and whose error named a live worker as dead.
  • The controller's kept-fd death probe and its off-thread death-callback reap are serialized by a per-slot reap-owner word: two reapers can no longer enter on the same open file description (flock re-acquire on one OFD always "succeeds", and the first finisher's unlock dropped the grant under the other — a respawn could then join mid-reap and have its fresh PENDING failed DIED by the straggler). The protocol is pure userspace CAS, so Windows same-handle LockFileEx semantics are irrelevant.
  • The ring-claim backpressure wake now fences memory_order_seq_cst before the full_waiters load, like the other two pusher sites — a relaxed load after the head CAS had no Dekker guarantee on ARMv8 (a missed bit cost the submitter a bounded 2 s sleep).
  • The string_view element accessor's buffer bound (mizu_arrow_str_at's view form, the ext tier's dual-form impl): a view record's buffer index was admitted up to n_buffers - 3, which indexes the trailing variadic sizes array the re-viewing producers append as if it were a data buffer, and a span was never checked against the declared size. The variadic data buffers are slots [2, n_buffers - 1): an index into the sizes slot is now malformed, and where the sizes array is present (non-NULL) a span past sizes[bi] declines — pymizu's pv_col_match_strview bound, promoted to the one shared definition. A frame carrying such a record declines at the open's size walk ("malformed offset or view record"), ahead of any emit. No wire change.
  • arrow_classify declines a timezone name past 63 bytes with an informative error instead of silently truncating it into the POSIXct blob (no silent downgrades; the longest zoneinfo key is 32 bytes, so no legitimate payload meets the bound).
  • mizu_na_build's REAL and CPLX element tests now discriminate the NA_real_ payload the way R's own ISNA does — any NaN whose low word is 1954 (0x7A2) — instead of matching only the quiet-bit-set MIZU_NA_REAL_BITS exactly, so a writer's quiet-bit-clear NA_real_ (R's verbatim form, 0x7FF00000000007A2) reads as NA on the validity-bitmap paths. No ABI or wire change (the helpers are unreleased, Phase 0).
  • A host-side death probe before the peer has attached no longer reads a verdict from the peer's untaken liveness lock: chan_probe_dead gates on the ready word (host side only), so the full-ring disambiguation returns MIZU_FULL and mizu_channel_alive reports no verdict instead of unrecoverably unlinking the channel pre-rendezvous.
  • A receive with the death-listener flag set but the lock probe reading HELD (a forked child or squatter outliving the peer holds the lock's open file description) no longer spins unboundedly at 100% CPU with the deadline and the interrupt hook unpolled: once the probe has returned HELD the one-shot flag stops vetoing the park, and the bounded park re-probes on every wake until the last holder exits.
  • A fork-without-exec child (an mclapply worker, a multiprocessing child) no longer keeps a dead holder's liveness lock alive past its death: every lock fd the library hands out is tracked, and a pthread_atfork child handler closes the child's copies (closing one fd of a duplicated pair never releases the parent's flock). mizu_live_close is registry-gated, so a stale handle fd in the child can never close a descriptor since reused. POSIX only — Win32 handles were never inheritable.
  • A consumer can once more drain to MIZU_CLOSED when the producer destroyed (or died) with a spilled payload in flight: the vanished region fails its one read, and a gone failure with the producer closed or verdict-dead is consumed exactly as MIZU_READ_CONSUME instead of wedging the ring behind the slot forever.
  • An orderly submitter detach frees its registry slot: with nothing PENDING, handle teardown cancels nothing — it frees the published-but-uncollected results (releasing the producing workers' keepers, exactly as the reaper would) and marks the slot FREE ahead of the lock close. With PENDING work the slot stays LIVE and the next attach's claim scan probes it (identity-checked lock acquire, then the reaper's sweep) instead of skipping it — a live process is never denied attach by a dead registration.
  • mizu_pool_leave now fails every result slot still stamped with the worker's slot, not just the announced in-flight claim: a nested claim overwrites the announce, and an orderly leave runs no death reaper to fail the overwritten claims — their collectors parked forever.
  • A worker join failing after its slot CAS (parkers attach, scratch allocation, owner watch) hands the slot back to FREE instead of leaving it CLAIMING until the stop sweep.
  • The Linux orphan prune scan now requires the exact region grammar (mizu_<pid>_<counter>, both hex): the liveness lock files sharing /dev/shm (....live.host, ....wk.0, ....owner, ...) are no longer enumerated as regions and unlinked from under live workers.
  • mizu_stage_raw_spill rejects a non-atomic wire_type (no element size) at entry instead of dividing by zero in the flat SHM_VEC reserve — binding misuse declines to the serialized tiers.
  • mizu_live_fd_bounce covers fds 1/2, not just 0: launched with stdout/stderr closed, a lock fd landing there would have been released by a later dup2/freopen onto it (a false DEAD).
  • The lent-region ledger's quota sweep rotates its start across calls (sweep_next): four or more long-held regions at the ledger front no longer starve every entry behind them on the busy-path sweeps.
  • Wire-carried region names are gated on the exact grammar (the prefix plus <hex>_<hex>) at mizu_read_region and mizu_shm_open_view_flags before any concatenation into /dev/shms: a /../ name from a corrupt or hostile peer no longer opens an arbitrary same-user file.
